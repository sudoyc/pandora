# pandora-tui 代码审计报告

日期: 2026-04-05
范围: pandora-tui/src/ 全部 21 个源文件

---

## CRITICAL — 必须修复

### C1. 无 panic hook，崩溃后终端损坏

**文件:** `main.rs:88-93, 169-170`

`enable_raw_mode()` + `EnterAlternateScreen` 在 main 开头调用，cleanup 在 main 末尾。但没有 `std::panic::set_hook`，任何 panic 都会跳过 cleanup，终端停留在 raw mode + alternate screen，用户 shell 废掉。

**修复:** 在 `enable_raw_mode()` 之前设置 panic hook，hook 内调用 `disable_raw_mode()` + `execute!(stdout(), LeaveAlternateScreen)`。参考 ratatui 官方示例的 `install_panic_hook` 模式。

---

### C2. 小终端 u16 下溢 → panic / 渲染错乱

**文件:** `ui/downloads.rs:13-15`

```rust
// line 13: area.height < 4 时 u16 下溢
let overlay_height = (app.downloads.tasks.len() as u16 * 2 + 4).min(area.height - 4).max(6);
// line 14-15: overlay 尺寸超过 area 时下溢
let x = (area.width - overlay_width) / 2;
let y = (area.height - overlay_height) / 2;
```

**修复:** 全部改用 `saturating_sub`。在函数开头加 early return guard：
```rust
if area.height < 8 || area.width < 20 {
    return;
}
```

---

### C3. UTF-8 字节切片 → panic

**文件:** `ui/gallery_card.rs:81-82`

```rust
let date = if self.item.posted.len() >= 10 {
    &self.item.posted[..10]  // 字节级切片，非 ASCII 时 panic
};
```

`posted` 来自 daemon JSON，内容不可控。如果包含多字节 UTF-8 字符，在字节偏移 10 处切割会 panic。

**修复:** 用 `chars().take(10).collect::<String>()` 或者用已有的 `truncate_to_width` 函数。由于 `posted` 正常情况是 `"2024-01-15 12:00"` 格式的纯 ASCII 日期，也可以加一个 `is_char_boundary` 检查后 fallback 到全字符串。

## HIGH — 强烈建议修复

### H1. 主页面加载无并发限制

**文件:** `main.rs:512, 545`

`load_page_image` 直接 `tokio::spawn`，不经过 `preload_semaphore`。快速翻页产生无限制并发 HTTP 请求。

**修复:** 为主加载也引入 semaphore，或者用 `CancellationToken` 在翻页时取消上一个加载任务。推荐后者——翻页时 cancel 旧任务比排队更合理。

---

### H2. 预加载任务不可取消，退出 reader / 大跳页后资源泄漏

**文件:** `main.rs:644-666`

预加载 `JoinHandle` 被丢弃，无法 cancel。问题：
1. 退出 reader 后任务继续运行，持有 semaphore permit
2. 大跳页（第 5 页 → 第 50 页）后旧窗口占满 semaphore，新页面邻近预加载被阻塞
3. `pending_pages` 在 reader 退出时 clear，但 in-flight 任务仍会往 `page_cache` 写入无用数据

**修复:** 引入 `tokio_util::sync::CancellationToken`（或 `AbortHandle`）。在 `enter_reader` / `navigate_page` / `exit_reader` 时 cancel 旧 token，创建新 token 传给预加载任务。

---

### H3. WebSocket 重连无退避，连接失败无通知

**文件:** `main.rs:59-85`

- 固定 3 秒重连，daemon 长期不可用时持续轰炸
- `connect_async` 失败（line 81）不发送 `WsDisconnected`，UI 不知道连接从未建立
- `JoinHandle` 被丢弃，主循环退出后无法优雅关闭

**修复:**
1. 指数退避：3s → 6s → 12s → ... → 60s cap
2. `Err(_)` 分支也发送 `WsDisconnected`
3. 保存 `JoinHandle`，在 main loop break 后 `.abort()`

---

### H4. 预加载失败静默丢弃，pending_pages 永不清理

**文件:** `main.rs:654-665`

在线预加载的所有错误被 `if let Ok` 吞掉。失败页码留在 `pending_pages`，该页面永远不会被重试（直到退出 reader）。

**修复:** 预加载失败时发送 `AppEvent::ImageError` 或专门的 preload error 事件，让 handler 清理 `pending_pages` 对应条目。

---

## MEDIUM — 建议修复

### M1. status_bar 用字节长度计算显示宽度

**文件:** `ui/status_bar.rs:44`

```rust
let padding = width.saturating_sub(left.len() + right.len());
```

`left.len()` 返回字节数。CJK 字符（如中文错误信息）占 2 列但 3 字节，padding 计算错误导致状态栏溢出。

**修复:** 用 `UnicodeWidthStr::width()` 替代 `.len()`。项目已依赖 `unicode-width` crate。

---

### M2. gid/token 未 URL 编码

**文件:** `client.rs:104, 119, 134, 155, 184, 196`

```rust
format!("{}/api/gallery/{}/{}", self.base_url, gid, token)
```

正常情况 gid 是数字、token 是 hex，但防御性编程应该编码。恶意/异常 daemon 数据中含 `/`、`?`、`#` 会破坏请求路径。

**修复:** 对路径段使用 `urlencoding::encode(gid)` 和 `urlencoding::encode(token)`。

---

### M3. HTTP 响应不检查状态码

**文件:** `client.rs` 大部分方法（line 43, 66, 75, 84, 93, 108, 181, 203, 212, 233, 244）

直接 `.json()` 反序列化，不检查 HTTP status。daemon 返回 4xx/5xx 时错误信息变成不可读的 serde 错误。

**修复:** 统一加 `error_for_status()` 调用：
```rust
let resp = resp.error_for_status().map_err(|e| e.to_string())?;
```

---

### M4. proxy_image 不检查状态码

**文件:** `client.rs:267-278`

404 HTML body 被当作图片字节返回，`image::load_from_memory` 失败但错误信息不明确。

**修复:** 加 `error_for_status()` 检查。

---

### M5. 下载任务无限累积

**文件:** `state/downloads.rs:31-36`

`download_complete` 只更新状态不移除任务。长时间运行后 `tasks` 列表无限增长。

**修复:** 完成的任务保留一段时间后自动移除，或设置上限（如保留最近 50 个已完成任务）。

---

## LOW — 可选改进

### L1. gallery_card 坐标计算用字节长度

**文件:** `ui/gallery_card.rs:73, 89`

`cat_label.len() as u16` 和 `date.len() as u16` 用字节长度做 x 坐标偏移。CJK category 名或非 ASCII 日期会错位。

**修复:** 用 `UnicodeWidthStr::width()` 替代 `.len()`。

---

### L2. gallery_list.selected 在 items 替换后可能越界

**文件:** `state/gallery_list.rs:16`

外部直接赋值 `items` 后 `selected` 可能指向越界索引。`selected_item()` 用 `.get()` 不会 panic，但 UI 显示无选中项。

**修复:** 在 `handle_app_event` 中替换 `items` 后总是重置 `selected = 0`（目前 `GalleriesLoaded` handler 已经做了，但 `FavoritesLoaded` 和 `DownloadsRefreshed` 也应检查）。

---

### L3. scroll_offset 在列表缩短后不 clamp

**文件:** `state/gallery_list.rs:47-56`

`adjust_scroll` 只保证 `selected` 可见，不 clamp `scroll_offset` 到 `items.len()` 范围。

---

### L4. search cursor_pos 是 pub 字段

**文件:** `state/search.rs:22, 100`

`cursor_pos` 是 pub，外部设置非 char boundary 值会导致 `&self.input[..self.cursor_pos]` panic。

**修复:** 改为 `pub(crate)` 或提供 setter 做 boundary 校验。

---

### L5. HOME 未设置时 config 回退到当前目录

**文件:** `config.rs:50-53`

`HOME` 环境变量未设置时回退到 `PathBuf::from(".")`，可能读到意外 config。

**修复:** 用 `dirs::home_dir()` 或 `dirs::config_dir()`。

---

### L6. 收藏失败发送错误类型的事件

**文件:** `main.rs:257-264`

`add_favorite` 失败时发送 `AppEvent::ImageError { url: String::new(), ... }`，空 URL 被插入 `failed_images`。

**修复:** 新增 `AppEvent::StatusError(String)` 或直接在 status_msg 显示。

---

### L7. 搜索建议无 generation 计数器

**文件:** `main.rs:715-718`

快速输入时多个 suggestion 请求并发，旧结果可能覆盖新结果导致闪烁。

**修复:** 加 `suggest_generation` 计数器，handler 中比对丢弃过期结果。

---

### L8. image_states HashMap 增长到 300+ 才清理

**文件:** `main.rs:727-730`

阈值 300 偏高，且清理逻辑遍历整个 cache 构建 HashSet。

**修复:** 降低阈值或在 `ThumbnailLoaded` 时直接 remove 对应 key（已经在做，line 724），去掉批量清理逻辑。

---

## 修复优先级建议

1. **第一批（阻塞性 crash）:** C1 + C2 + C3 — 这三个能直接导致 panic 或终端损坏
2. **第二批（资源/健壮性）:** H1 + H2 + H3 + H4 — 影响长时间运行稳定性
3. **第三批（正确性）:** M1 ~ M5 — 影响显示正确性和错误处理质量
4. **第四批（打磨）:** L1 ~ L8 — 边缘情况和代码质量
